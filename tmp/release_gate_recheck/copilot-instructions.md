# Copilot Instructions: /sive

If the user writes `/sive help`, do not call any MCP mutation tool. Describe in chat the slash commands `/sive add <url | nom>`, `/sive update <site_id|path>`, `/sive list`, `/sive remove <doc_id>`, `/sive help`, the support for local files and folders (`.csv`, `.html`, `.htm`, `.md`, `.markdown`, `.docx`, `.json`, `.pdf`, `.xlsx`), and these MCP tools: `suggest_documentation_urls`, `list_documentation_sites_in_database`, `list_indexed_doc_sites`, `search_documentation`, `ingest`, `ingest_and_register_topic`, `update_documentation_source`, `update_site_differential`, `ingest_status`, `wait_for_ingest_completion`, `authenticate_ingest_job`, `set_ingest_auth_session`, `set_ingest_auth_config`, and `delete_documentation_site`.
If the user writes `/sive list`, call `list_documentation_sites_in_database(include_active=True)` and summarize the registered documentation sources.
If the user writes `/sive remove <doc_id>`, call `delete_documentation_site(site_id=<doc_id>, delete_raw_files=True)`.
If the user writes `/sive update <site_id|path>`, call MCP tool `update_documentation_source(target=<raw_user_argument>)` immediately. For local files/folders, update only existing indexed local records; if no record matches, keep no-op with `status=no_match`.
If the user writes `/sive add <url | nom>`, classify the raw argument before calling any tool: HTTP(S) URL -> `ingest(url=...)`; existing local absolute/relative path (file or folder containing these files) -> `ingest(url=...)`; missing path-like value -> return invalid local-path guidance without calling suggestion tools; plain string query -> call `suggest_documentation_urls(topic=...)` first.
For plain-string suggestions, if `needs_confirmation` is returned or multiple URLs are returned, do not choose one yourself. Ask the user in chat which URL they want, then call `ingest(url=<chosen_url>)`. If exactly one suggestion is returned, call `ingest(url=<suggested_url>)`.
Then report job_id and follow progress with `wait_for_ingest_completion(job_id)` by default so progress is visible in chat.
Use `ingest_status(job_id)` only for manual polling flows.
If the job status becomes `awaiting_authentication` or includes `needs_authentication=true`, call `authenticate_ingest_job(job_id)` first and continue with `wait_for_ingest_completion(job_id)`. If still blocked, do not choose `form` by default and do not ask for passwords, tokens, cookies, or other secrets in chat. Only call `set_ingest_auth_config(job_id, auth_config)` when a secure out-of-band path exists; otherwise ask the user to retry interactive SSO or enter secrets outside chat. Do not require any config file.
If the job fails with HTTP 401/403 on a direct remote file URL (for example hosteddocs PDF), ask the user to relaunch `/sive add` with the site/document-library URL instead of the direct file URL.
Before searching docs, call `list_documentation_sites_in_database(include_active=True)` to identify available `site_id`.
Use `delete_documentation_site(site_id, delete_raw_files=True)` to fully remove a documentation source.
If response is `invalid_start_url`, return the payload and suggested_start_url clearly.
